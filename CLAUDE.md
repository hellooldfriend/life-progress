# Doozy — контекст проекта для ИИ

Личный и рабочий планировщик по горизонтам: **день → неделя → месяц → квартал → год**, плюс
«Входящие» без даты. Одна задача видна и как шаг недели, и как часть годовой цели. Кроме плана
есть память: у каждого периода свободный текст «итоги» (что было, что получилось).
Vanilla HTML/CSS/JS, без сборки и бэкенда, работает с `file://`. Общение с пользователем — по-русски.

Приложение называется **Doozy** (выбрано 6 сентября 2026; «a doozy» — нечто выдающееся). Папка
проекта пока `life-progress` — её переименование за пользователем (`mv`), см. «Не сделано».
Интерфейс по умолчанию английский, русский переключается кнопкой `RU/EN`.

## Запуск и проверка

```bash
open index.html          # основной сценарий пользователя — двойной клик по файлу
npm test                 # node --test, ~110 тестов, секунда
npm run serve            # python3 -m http.server 4174; есть .claude/launch.json
```

Что важно знать при проверке в браузере (панель превью Claude Code):
- `file://` панель отдаёт как снимок на `data:`-адресе — относительные `css/`, `js/` **не резолвятся**.
  Проверять через http-сервер. Настоящий `file://` в реальном браузере работает (обычные `<script src>`).
- Клавиша `Return` в автоматизации приходит с пустым `key`; используй `Enter`.
- Замер геометрии сразу после `navigate` бывает стар — подожди ~150 мс.
- При эмуляции вьюпорта (`resize_window`) координаты кликов расходятся со скриншотом; клики — на
  «desktop», размеры проверять через JS.
- Диалог выбора файла (`showSaveFilePicker`) из автоматизации не открывать — не закроется.
- После проверки чистить `localStorage` и `indexedDB('doozy')`, гасить сервер.

## Архитектура

| файл | роль |
|---|---|
| `index.html` | каркас; статичные подписи помечены `data-i18n` / `data-i18n-title` |
| `css/styles.css` | токены дизайн-системы (те же имена, что в `../sprint-progress`) + компоненты |
| `js/i18n.js` | словарь `en`/`ru`; `I18N.t(key, ...args)`; всё языковое, включая формат дат и склонения |
| `js/store.js` | модель, персистентность, даты, ключи периодов, CRUD — единственный, кто знает про localStorage |
| `js/insights.js` | выборки для дашборда, чистые функции над Store, без DOM |
| `js/filesync.js` | автосохранение в файл (File System Access API), перенос из sprint-progress |
| `js/ui.js` | рендер: строки → `innerHTML`; локальное состояние вида |
| `js/app.js` | обработчики событий (делегирование), горячие клавиши, старт |
| `tests/` | `node --test`; `helpers/load.js` склеивает `i18n`+`store`+`insights` в vm-контекст |

Паттерн модуля — `const Store = (() => { 'use strict'; ...; return {...}; })();`, обычные скрипты
в порядке зависимостей: `i18n → store → insights → filesync → ui → app`. **ES-модули нельзя**
(CORS на `file://`). Сборки нет и не нужно. Комментарии в коде — по-русски, объясняют «почему».
Пользовательские строки — только через `I18N.t`, литералов в `ui.js`/`app.js` быть не должно.

## Модель данных (`Store`, версия 3, ключ `doozy:v1`)

```js
{
  version: 3,
  settings: { horizon: 'overview', lang: 'en',
              spans: { day: 14, week: 1, month: 1, quarter: 1, year: 1 },
              visible: { day: true, week: true, month: true, quarter: true, year: true } },
  periods: {
    'inbox':      { tasks: [...], summary: '' },   // входящие: периода нет
    '2026-08-29': { tasks: [...], summary: '' },   // день
    '2026-W35':   { tasks: [...], summary: '' },   // ISO-неделя
    '2026-08':    { tasks: [...], summary: '' },   // месяц
    '2026-Q3':    { tasks: [...], summary: '' },   // квартал
    '2026':       { tasks: [...], summary: '' },   // год
  }
}
task: { id, text, category, parentId, done, doneAt, important, cancelled, cancelledAt,
        carriedFrom: { key } | null, carryCount, createdAt }
```

- **Ключ периода кодирует горизонт**; `keyHorizon(key)` — единственная проверка «наш ли ключ»,
  через неё идёт и импорт (отсекает `2026-13`, `2026-02-31`). Даты всюду ISO-строки в местном времени.
- `inbox` — обычный список задач без границ: `keyStart/keyEnd/nextKey` → `null`, поэтому он сам
  выпадает из просрочки и напоминаний.
- Инварианты: `done` и `cancelled` взаимно гасятся; пустые периоды вычищаются в `save()`;
  `parentId` — только id (перенос цели не рвёт связь), битые ссылки чинятся в `normalize`;
  `carriedFrom` хранит только `key` — подпись считается на текущем языке.
- Миграция: читаются старые ключи `life-progress:v1` и `life-sprints/v1` (первый непустой в этом
  порядке); `ui.view`→`settings.horizon`, `range`→`spans.day`; отсутствующий `lang` → `en`;
  `visible` без единого `true` сбрасывается. Любой мусор в `normalize` молча отбрасывается.
- Видимость горизонтов: `isVisible/visibleHorizons/setVisible` — последний видимый спрятать нельзя.
  Скрытый горизонт уходит из вкладок, обзора, разбивок и кнопок «куда разобрать»; задачи в нём
  остаются и по-прежнему попадают в просрочку.

Ключевые операции: `carryTask(key,id,target?)` — перенос с пометкой (`carryCount++`, тег «перенос из»);
`fileTask(from,id,to)` — планирование без пометки (входящие, шаги цели);
`orderedTasks` — показ: активные → выполненные → отменённые, ручной порядок в массиве не трогается;
`stats(key, category?)` — отменённые не в знаменателе; `setParent` с защитой от колец;
`goalCandidates`; `periodSpan(key,n)`; `spanTitle(a,b)` схлопывает повторы («Week 35 — 37»).

`Insights.attention(today)`: просрочка = `keyEnd < today` и есть открытые задачи (любой горизонт);
залипшие = `carryCount ≥ 2`, без дублей с просрочкой; ненаписанные итоги — только **последний**
закончившийся период каждого горизонта и только если в нём была активность.

## UI

- Вкладки: `days` (агенда) / `week` / `month` / `quarter` / `year`; вид `overview` без вкладки —
  на него ведёт логотип `.brand` (он же счётчик входящих). Приложение всегда открывается на обзоре.
- Обзор = Входящие → Сейчас (сегодня + видимые горизонты) → Разгрести (просрочено / залипло / итоги).
- Кнопка `⚙` открывает полосу `#settings` с чекбоксами горизонтов (`UI.setVisible`); если спрятали
  вкладку, на которой стоим, — уходим на обзор. Кнопки «сегодня / неделя / месяц» — это первые три
  **видимых** горизонта (`FILE_TARGETS`).
- Итоги видны и из родителя: карточки недель в месяце, кварталов и месяцев в году, окна периодов
  показывают выдержку (`excerptHTML`), редактируется итог только в своём виде.
- Ширина окна на горизонт (`settings.spans`): 1 — карточка + разбивка на подпериоды и редактируемые
  итоги; >1 — соседние периоды в одну строку (`.span-grid`: `minmax(240px,1fr)`, скролл вбок, на
  телефоне колонка), без стрелок порядка. Стрелки ← → сдвигают окно на один период.
- Строка задачи `.task` (`data-key`, `data-id`) — везде одна и та же разметка, включая дашборд и
  список шагов под целью; обработчики в `app.js` делегированы на `#content` по `data-act`.
  Панель шагов `.steps-panel` лежит вне `.task`, поэтому `closest('.task, .steps-panel')`.
- Галочка правится в DOM на месте, перерисовка через 220 мс (`renderAfterAnimation`), чтобы
  анимация доигралась, а задача потом уехала вниз. Правка текста — подмена `span` на `input`,
  в поле текст вместе с меткой (`taskInputValue`).
- Метки — `#слово` прямо в тексте (`parseTaskInput`), фильтр-чипы над контентом; фильтр и
  раскрытые панели живут в `UI.view` / `expanded` и не сохраняются.
- Ловушки вёрстки (комментарии в CSS есть): `min-width: 0` на `.task` (грид-элемент) и на
  `.task__text` (флекс-элемент), иначе строка вылезает за карточку; теги с `text-overflow: ellipsis`.
- Клавиши: `← →` период, `t` к текущему, `i` записать во входящие (работают и в русской раскладке).

## Тесты

`loadApp(seed?)` поднимает свежий `{ I18N, Store, Insights, storage }` с localStorage в памяти;
`seedTasks(Store, key, items)`. Имена тестов — русские предложения, в assert'ах — «почему».
Файлы: `dates`, `periods`, `spans`, `tasks`, `categories`, `workflow` (отмена/порядок/перенос),
`inbox`, `goals`, `insights`, `storage` (миграции), `i18n`, `visibility`. UI и filesync тестами не покрыты —
проверяются в браузере.

## Продуктовые решения (не переделывать без причины)

- Копии при переносе нет — память в `carriedFrom`/`carryCount`; на 2-м переносе тег «3rd day in a row».
- Отмена ≠ невыполнение: задача видна, но вне прогресса. Перенос снимает отмену.
- Галочка во входящих кладёт задачу в сегодняшний день закрытой — входящие должны пустеть.
- Кнопки «сегодня / неделя / месяц» кладут в **текущий** период, подсказка называет какой.
- Шаги показываются на один уровень; цель не закрывается автоматически по шагам.
- Шаг, лежащий в периоде цели, показывается один раз — под целью.
- На дашборде нет burn-down/velocity/streak: если по цифре нельзя кликнуть — её там нет.
- Итоги есть у недели тоже (сверх исходного ТЗ) — для «спринтов» это самая полезная ретро.
- Палитра: тёмная, акцент индиго `#8b5cf6` из sprint-progress, остальное монохром.
